1. 전체 시스템 구성

센서에서 측정한 물리량이 앱 화면과 AI 판정에 이르기까지의 경로입니다.

설계 요점. ESP32 한 개가 광원 구동·수광 측정·신호 처리를 모두 담당합니다. 별도의 연산 증폭기나 커패시터 없이 R-DAC + ADC 조합만으로 아날로그 프런트엔드를 대체해, 부품 수와 실패 지점을 줄였습니다. 앱은 화면 로직을 그대로 둔 채 Capacitor로 감싸 네이티브 BLE만 연결합니다.

2. 탁도 측정 원리 — 왜 비율(ratio)로 재는가

단순히 "받은 빛의 양"을 재면 LED가 늙거나 온도가 변할 때마다 값이 흔들립니다.
보낸 빛과 받은 빛을 동시에 재서 비율로 환산하면 이 변동이 상쇄됩니다.

주변광을 지웁니다. 분모의 나눗셈이 LED 밝기 변화를 지웁니다. 남는 건 물의 탁한 정도뿐
왜 이 구조가 필요한가.
① 주변광 제거 — 어항 조명은 켜졌다 꺼집니다. LED를 끈 상태와 켠 상태를 매번 쌍으로 재서 빼면, 조명이 바뀌어도 값이 흔들리지 않습니다.
② LED 변동 제거 — IR LED는 온도와 사용 시간에 따라 밝기가 변합니다. 션트 저항으로 실제로 흘린 전류를 함께 재서 나누면, 밝기가 달라져도 같은 물에서는 같은 값이 나옵니다.
③ 최종 환산은 램버트-비어 법칙을 따릅니다. NTU = K × (−log₁₀(ratio / ratio_clear))

3. 1회 측정 시퀀스 (1초 주기)

구동 세기를 자동으로 골라 ADC 포화를 피하고, 매번 암전류를 새로 잡습니다.

오토레인징이 필요한 이유. 맑은 물에서는 빛이 거의 그대로 도달해 ADC가 포화되고, 탁한 물에서는 신호가 너무 약해집니다. 고정된 세기로는 두 상황을 모두 커버할 수 없습니다.
펌웨어는 부팅 시 8단계의 실제 전류를 직접 측정해 순서를 정하므로, 어느 GPIO에 어느 저항이 물렸는지와 무관하게 항상 올바르게 동작합니다.

4. 앱의 상태 판정과 알림 흐름

측정값을 그대로 보여주는 대신, 어종별 기준과 비교해 상태로 바꾸고 변화가 있을 때만 알립니다.
