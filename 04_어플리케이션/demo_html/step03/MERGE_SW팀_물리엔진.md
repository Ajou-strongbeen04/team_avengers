# 병합 기록 — SW팀 용존산소 물리엔진 → 안드로이드 앱

**날짜** 2026-08-01 · **병합 방향** 안드로이드 셸(이 프로젝트)을 베이스로, SW팀 물리엔진을 이식

---

## 0. 왜 이 방향인가

두 `app_demo.html` 은 "누가 더 최신" 이 아니라 **공통 조상에서 서로 다른 방향으로 갈라진 포크**였다.

| | 이 프로젝트 (89 KB) | SW팀 사본 (114 KB) |
|---|---|---|
| Capacitor 패키징 · BLE(ESP32) | **있음** | 없음 |
| 센서 고장판정 · 클리어워터 교정 | **있음** | 없음 |
| 알림 디바운스 · 알림로그 · 미읽음 배지 | **있음** | 없음 (단순 브라우저 푸시) |
| 탭 구조 · XSS 이스케이프 | **있음** | 없음 |
| 용존산소 물리모델 | 자리표시자 | **있음** (rev.C) |
| A층 ROM (CFD 315케이스) | 없음 | **있음** |
| 폭기 용량 진단 · 권장조치 | 없음 | **있음** |

→ 알림·센서·패키징은 이 프로젝트 쪽이 확실히 낫다. 그래서 **이쪽을 베이스로 두고
물리만 가져왔다.** SW팀의 `checkAllAlerts` / `sendBackgroundNotification` 은 버리고
이 프로젝트의 `commitTransition` 디바운스 체계를 그대로 썼다.

## 1. 추가된 파일

| 파일 | 크기 | 역할 |
|---|---|---|
| `do_engine.js` | 26 KB | 용존산소 수지 · 폭기 진단 · ROM 추론 (rev.C) |
| `rom_model.js` | 210 KB | CFD 315케이스로 학습한 A층 ROM 계수 |

`rom_model.js` 가 없어도 `do_engine.js` 는 근사식으로 자동 폴백한다 (산소 분포 지도만 비활성).
`do_engine.js` 가 없으면 `estimateHealth()` 가 옛 선형 근사식으로 되돌아가 앱은 계속 동작한다.

**엔진은 전역을 참조하지 않는다.** 앱이 `syncEngine()` 으로만 상태를 밀어넣는다.
따라서 물리 계수를 고칠 때 `app_demo.html` 을 열 필요가 없다.

## 3. 산소 계산식

```
C = C*(T) − R_total / (V · K_La)            (완전혼합 정상상태)

C*(T)   Benson–Krause 담수 포화 DO             C*(25) = 8.2635 mg/L
R_total 어류 + 유기물(탁도) + 식물(주야)
K_La    (플룸·에어스톤높이 + 자유수면) × 수위 × θ_a^(T−25)
        정본 운전점 3.618 /h = 플룸 3.174 + 자유수면 0.444
V       사용자 수조 치수 × 수위               기준 20.7 L
```

**등급은 평균이 아니라 최저 지점 기준이다.** 평균이 안전해도 바닥 구석이
임계(6.0 mg/L) 미만이면 그 물고기는 실제로 숨이 차다.

완전혼합 축약의 근거: 폭기 플룸 이류 순환 12.8 s vs 산소 소비 9.5 h → **2,673배**.
축약 오차는 결핍 기준 3.8 %, DO 기준 0.11 % (0.0091 mg/L).

## 4. 알림 — 세 지표 독립 판정

수온 · 탁도 · **용존산소**를 각각 별도 채널로 판정한다. 산소는 센서로 직접 재는 값이
아니라 두 센서값에서 계산되지만, 수온·탁도가 각각 정상 범위여도 둘이 겹치거나
사육부하가 크면 **산소만 먼저 무너질 수 있다.**

기존 디바운스 규칙(`ALERT_STABLE_COUNT` 3회 · `ALERT_MIN_GAP_MS` 60 s)을 그대로 태운다.

검증 결과 (금붕어, 47×21×21 cm, 폭기 보통):

| 시나리오 | 입력 | 판정 | 알림 |
|---|---|---|---|
| 전부 정상 | 20.5 °C / 5 NTU / 3마리 | 양호·양호·양호 | 없음 |
| 온도만 위험 | 31 °C / 5 NTU / 3마리 | **경고**·양호·주의 | 2건 |
| 탁도만 위험 | 20.5 °C / 40 NTU / 3마리 | 양호·**경고**·양호 | 1건 |
| 산소만 위험 | 20.5 °C / 5 NTU / 80마리 | 양호·양호·**경고** | 1건 |
| 세 개 동시 | 31 °C / 40 NTU / 80마리 | **경고·경고·경고** | **3건** |

「온도만 위험」에서 산소가 주의로 함께 뜨는 것은 오류가 아니다 — 31 °C 는 포화농도를
낮추고 대사율을 올리므로 물리적으로 산소 여유가 실제로 줄어든다.

## 5. 기기(백그라운드) 알림 — 남은 한 단계

현재 알림 경로는 두 개이고, **둘 다 없으면 앱 안의 알림 목록에만 남는다.**

1. **Capacitor LocalNotifications** — APK 에서 쓰는 정식 경로. 런타임에 플러그인이
   있을 때만 잡히도록 feature-detect 했다. 아직 **미설치**다.
2. **Web Notification API** — 브라우저에서 열었을 때의 폴백.

APK 에서 진짜 백그라운드 알림을 받으려면 한 번만 해주면 된다:

```bash
npm i @capacitor/local-notifications && npm run sync
```

플러그인이 Android 13+ 의 `POST_NOTIFICATIONS` 권한을 매니페스트에 자동으로 넣는다.
하드 의존으로 두지 않은 이유는, 지금 상태에서도 빌드가 깨지지 않고 앱이 동작해야 하기 때문이다.

`node` 가 없는 PC 였으므로 로컬 서버 + 브라우저로 실행 검증했다.

```bash
python -m http.server 8765 --bind 127.0.0.1
# → http://127.0.0.1:8765/app_demo.html
```

| 항목 | 결과 |
|---|---|
| `V`, `K_La` @기본조건 | 20.73 L, 3.618 /h — 정본 일치 |
| `C*(25)` | 8.2635 mg/L — Benson–Krause 일치 |
| 금붕어 3마리 소비량 | 18.00 mg/h — 논문 기준값 일치 |
| `C = C* − R/(V·K_La)` | 엔진 7.9594 = 손계산 7.9594 |
| 점유격자 | 768셀 (8×8×12), 장애물 반영 확인 |
| ROM 최저점 | 바닥 먼 구석 — 물리적으로 타당 |
| S1 형상 게이트 | 폭기 '강' → `romGated=true`, 지도 대신 사유 표시 |
| 히트맵 | 96셀 렌더 · ★ 폭기 근처 고산소, 먼 곳 저산소 |
| 알림 3채널 독립 | 위 §4 표대로 통과 |

**발견해 고친 버그 1건:** `rom_model.js` 는 `const ROM_MODEL = {...}` 로 선언하는데,
고전 스크립트의 top-level `const` 는 스크립트 렉시컬 스코프에 묶여 **`window` 에 붙지 않는다.**
엔진이 처음에 `window.ROM_MODEL` 로 읽어 `romAvailable()` 이 항상 false 였고, ROM 이
조용히 비활성됐다 (근사식으로 폴백돼 눈에 띄지 않았다). 맨이름 참조로 수정.

## 7. 아직 안 한 것 / 넘길 것

- **APK 실기기 확인 미수행** — 이 PC 에 node/Android SDK 가 없어 `npm run sync` 를 못 돌렸다.
  `www/` 와 `android/.../assets/public/` 에는 수동으로 복사해 뒀으니, 다음 빌드 때
  `npm run sync` 를 한 번 돌려 정상 반영을 확인해 주면 된다.
- **API 키가 HTML 에 그대로 박혀 있다** (`API_KEY`). 파일을 받은 사람 전원이 키를 볼 수 있고
  분당 할당량을 공유한다. 팀 내부 테스트까지는 괜찮지만 외부 배포 전에 서버 프록시가 필요하다.
- 기계팀 결정 대기 항목은 SW 소관이 아니다: `u_plant` 기저(S2 근본해결), 운전점별 χ(S1),
  `U_slip(T)`·§4.2 펌프동력 역산(N4), U1~U4 출처 귀속.
