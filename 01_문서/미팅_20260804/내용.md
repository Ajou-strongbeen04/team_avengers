## 1. 프로젝트 주제의 전환 이유

### 1-1. 기존 문제의식과 그것이 깨진 지점

이송-확산 방정식에서 **유속항(advection)이 지배적**이라고 보고, 가두리 양식장 내부 유속 프로파일 확보를 목표로 했다.

CFD 해석 결과가 그 전제를 부정했다 — **4×8 직사각 배치 · 10×10×10 m 정사각 케이지**에서 연안 기준 **외부 균일유동 0.3 m/s가 케이지 내부에 큰 영향을 주지 못했다.**

- 외부와 직접 맞닿은 케이지만 외부 유동의 영향을 받았다
- 안쪽을 감싸는 **2×6 케이지는 유속이 거의 0에 수렴**했다
- 내부에 남는 것은 일정한 방향이 없는 난류성 유동뿐이었다

유속장을 직접 알아내려는 시도는 모두 실패했다 — CFD를 제외한 고전적 방정식 해석 실패, 케이지 전체를 검사체적으로 두는 방법 실패(다공성 구조 경계조건 파악에 CFD 필수).

### 1-2. 방정식으로 되돌아가서 얻은 것, 그리고 잃은 것

$$\frac{\partial C}{\partial t} + \nabla\cdot(UC) = \nabla\cdot(D_\text{eff}\nabla C) + \Sigma S$$

가두리 내부에서 $U \approx 0$, 정상상태 $\partial C/\partial t = 0$ 이면 남는 지배 인자는 **$\Sigma S$ 하나**다. 문제는 간단해졌다.

**그런데 문제가 간단해진 대가가 곧 주제의 한계였다.** 이송항이 사라지면 공간구조가 사라지고, 공간구조가 없으면 "어디가 위험한가"를 물을 수 없다. AI융합 대회에서 다룰 대상이 남지 않는다.

### 1-3. 전환 (2026-07-11)

**산업 양식(가두리) 트랙 종료 → 가정용 어항 DO 공간분포 진단 디바이스.**

| | 가두리 (구) | 가정용 어항 (현) |
|---|---|---|
| 유동 | $U \approx 0$ → $\Sigma S$ 로 정상상태 DO 결정 | 폭기 와류로 유동이 정상상태에 **미수렴** |
| 해석 | 정상상태 | **과도상태(URANS · SST k-ω)** 후 시간평균 |
| 이송항 | 소거 | **유지** — 저산소역(공간구배)이 핵심 차별점 |
| $Pe$ | — | 플룸 $O(10\text{–}100)$ ~ 정체역 $O(0.1)$ 로 **공간변동** = 공간구조의 원인 |

- **포지션:** 자율주행이 아니라 **계기판 경고등** — 위험/안전/건강 판정만 한다
- **설계:** 실험(재폭기 시험 + CFD ground-truth) → 저가제품(프록시 센서 + 카메라 + 물리로 DO 장 재현) **2단계**
- **AI융합 대회 성격 반영:** 신규성 검토 결론이 "방법($K_La$ 캘리브레이션)은 교과서 표준, 새로움은 **가정 어항 × 사진기반 자동 BC × 소비자 공간 DO 진단의 통합**"이므로, 사진→BC 파이프라인을 헤드라인으로 세웠다

## 3. 논문

### 3-1. 방법론 (간략)

**(a) URANS + 이송확산 방정식으로 시뮬레이션–실제를 정량 분석**

- 폭기 와류로 유동이 정상상태에 미수렴 → 과도상태 URANS(SST k-ω) 계산 후 시간평균, DO는 스칼라 수송으로 이송항 유지
- 실측과의 이격을 **하나의 계수로 계수화**: $\kappa = K_La_\text{eff,meas} / K_La_\text{eff,CFD}$
- 실측은 **비정상 재폭기 시험**(Na₂SO₃ 탈산소 후 DO 회복 곡선 피팅). hold-out 축은 에어스톤 침지 높이 $z_\text{start}$
- 소스 닫음: $\alpha_g = U_{gs}/(W + U_\text{slip})$ drift-flux 고정점, $a = 6\alpha_g/d_b$, $W = 0.2178\,\mathrm{Su}^{0.511}$
- 생물 소비항(Monod)·저서 SOD는 모델에서 제거하고 어항별 BC로 분리(무저질 검증)

**(b) 생성형 AI 기반 경계조건 자동설정 및 물리 분석 DO값**

- 사진 1장 → Gemini 2.5 Flash → 기하·위상 JSON(정규화 [0,1] 좌표 + confidence)
- 좌표 변환 확정: $x = x_\text{img}L$, $y = z_\text{img}B$, $z = y_\text{img}d$ — **사진좌표 ≠ CFD좌표(2·3축 교환)**. `coords_img`와 `coords_cfd` 둘 다 필수 필드
- 인식 결과가 ROM의 경계조건·소스항 위치($\Omega_\text{air}$, $\Omega_\text{filter}$, $\Omega_\text{fish}$)로 들어간다
- A층(기하 → 시간평균 유동장) → B층(유동장 고정 후 DO 선형 스칼라) **2계층 분할** — 특허 독립항 B의 근거

- 주장 문장을 교체했다: "κ가 전이된다" → **"κ는 설계점 보정계수이고 CFD의 $z$ 레버는 과대하다"**
- 가설 (a) 기하 오차는 기각(에어스톤 방출중심 실측 20 mm = 기록값 일치), **가설 (d) 폭기 위치**가 부상 — 같은 Su에서 위치만 바꿔 $W$ +8.2 % / $\alpha_g$ −7.0 %, 효과가 $z$=0.02에 집중(−4.9 % vs −0.2 % vs +0.9 %) → 예상 κ 격차 10.5 %p → **약 6 %p**
- 멱법칙 적용 범위 확대 확인: $W \propto \mathrm{Su}^{0.511}$ 로 e02 오차 +0.06 %, e17(Su +37.4 %) −0.27 % → "국소 스케일 가정" 한계 서술을 완화할 근거
- 철회한 주장 2건: "t_mix ≪ 1/K_La, 벌크 균질"(위치 간 결손 산포 2.0–3.5배가 ≥10분 지속, 1/K_La = 24.8분), "3-D가 산포를 좁힌다"(0-D 13.33 % → 3-D 14.46 %)
- 대조군: CFD_v2 S1 가상 재폭기에서 **프로브 7점 간 CV 0.00 %** (실측 위치 산포 1.44 %의 대조)

#### (b) DO 공간구배는 **과하지 않은 구조물 내에서 없다**는 것을 정량적으로 확보했다

공간 진폭 정의 (부하 $R$ 이 소거되어 기하·유동만의 양):

$$A \equiv \frac{\overline{C}-C_\text{min}}{C^{*}-\overline{C}} = \frac{\chi_\text{max}-\overline{\chi}}{\overline{\chi}}$$

| 사육 부하 [마리] | 3 | 10 | 28 | 80 |
|---|---|---|---|---|
| $A$ | 1.7 % | 1.6 % | **1.5 %** | 1.5 % |

- $\chi$ 기저의 공간 산포 max/min = **1.06배**(상대폭 5.7 %)
- 금붕어 28마리·25 °C·바위+수초에서 평균 결핍 2.258 mg/L, **평균 − 최저 = 0.035 mg/L**
- 등급 밴드(양호↔주의) 1.5 mg/L 대비 공간항은 **밴드의 2.3 %**
- 선형계에서 고정 $\chi$ 형상을 스케일만 하므로 $A$ 가 부하와 무관한 것은 계산 결과가 아니라 **정리(定理)** → **"공간항이 등급을 뒤집을 경로가 구조적으로 없다"**

**이 음성 결과가 곧 VLM–ROM의 오차 예산을 열어준다.** 판정에 필요한 기하 정확도가 대폭 완화된다.

| 3D CNN (Stage 2-B) | 0.713 | 0.677 | 0.191 | 6.6 mm |
| **하이브리드(중첩 + 잔차 POD+RF)** | 0.668 | 0.686 | **0.276** | **5.9 mm** |
| POD projection ceiling | 0.293 | 0.861 | 0.494 | 2.7 mm |

- 구성별 분해(CV): **식물만 IoU 0.785(성립) / 혼합 0.568(경계) / 바위만 0.423(실패, 비가법)**
- energy 0.99 재실행에서 지표가 악화(6.6 → 7.9 mm) → 절단 가설 기각, **데이터 병목 확정**
- 유효범위 **구조물 0~2개** (Tier3 $n$=3~6 미학습). 이것이 제품 관점의 남은 제약이다

## 4. 앱 작동 시연 ★ (최종 산출물 — 최대 비중)

### 4-0. 이 구성이 왜 이렇게 생겼는가

DO 센서를 직접 넣으면 비싸고 드리프트한다. 그래서 **DO를 재지 않고 추론한다.**

```
[수온 · 탁도 2종 실측] ──┐
                          ├─▶ 물리 추론(C4) ─▶ DO 공간분포 ─┐
[사진 1장] ─▶ VLM(C2) ─▶ BC 자동설정(C3) ──┘                  ├─▶ 3항목 동등 융합 판정(C6)
                                                               │    위험/안전/건강 + 배치 처방
[빅데이터 건강도(C5)] ─────────────────────────────────────────┘
                              ▲
                    캘리브레이션(C7) — 실험 ground-truth로 저가 관측 보정
```

특허 C1~C7이 그대로 제품 블록도이고, 앱이 C2·C3·C4·C6의 구현체다. 최우선 신뢰성 요건은 **false-safe 방지**(죽어가는데 "안전"으로 뜨는 것)다.

### 4-1. 센서 설계

#### (1) 시스템 — 벽걸이 2-레그, 수선을 경계로 물리 분리

```
   ┌───────────────┐  ← 상단 브릿지 (수조 테두리, dry): MCU · BLE · 전원관리
   │  ESP32 + BLE  │     케이블 글랜드로 방수 관통
   └──┬─────────┬──┘
  [보드쪽 레그]  [센서쪽 레그]
   (dry)          (wet, IP68)
  ┌──────┐      ┌──────┐  ← waterline ≈ z=0
  │배터리│      │▓▓▓▓▓▓│   IR 탁도 광학존 (모듈·분리)
  └──────┘      │  ▽   │   DS18B20 스테인리스 팁 = 최저점(저층)
                └──────┘  Φ10 mm · 침지 ≈200 mm
```

| 항목 | 값 | 근거 |
|---|---|---|
| 프로브 OD | **Φ10 mm** | 침입성(유동교란) 최소화 |
| 침지 길이 | ≈200 mm | 수심 0.21 m 전층 커버, 팁이 $z$≈0.19–0.20 m 도달 |
| 장착벽 ↔ 프로브축 | **35 mm** | 벽걸이 폭기축과 **동일 기준** → 프로브를 저산소역 좌표에 재현성 있게 배치 |
| 플룸 회피 | 폭기 플룸 $r_p$=0.01 m(Φ20 mm) **밖** | 상승류에 직접 노출되면 저산소역을 못 본다 |
| 설계 철학 | 젖는 부분(센서)과 마른 부분(MCU·배터리)을 수선으로 분리, 미확정 2요소(IR 탁도·배터리)를 독립 모듈로 빼고 나머지를 먼저 freeze | — |

#### (2) 수온 — DS18B20 방수 프로브

스테인리스 캡 Φ6 mm급 3선. **팁을 프로브 최저점에 노출** — 최저점 수온이 저산소 위험판정에 직결(수온↑ = 포화 DO↓). 탁도 프로브의 온도보정 기준값도 여기서 받는다.

#### (3) 자체 제작 IR 탁도 센서 — v3.1 freeze (2026-07-27)

**왜 자체 제작인가.** 시판 IR 탁도 C안 부품 조사가 개략 합계 **약 32,000원**으로 나와 전면 폐기했다(*"발주하지 말 것"*). 대체는 **보유부품 전용 v3.1, 추가 구매 0원**.

**회로 — 능동부품이 ESP32 하나다**

| 부품 | 값 | 핀 |
|---|---|---|
| $R_{b2}$ / $R_{b1}$ / $R_{b0}$ | 150 / 330 / 680 Ω | `P27` / `P26` / `P25` → 노드 A (GPIO 3비트 R-DAC) |
| $R_\text{sense}$ | **22 Ω** | 노드 K → GND |
| SENSE ADC | — | **GPIO36 (`SVP`)** ← 노드 K |
| $R_L$ | 15 kΩ (잠정) | 노드 N → GND |
| SIG ADC | — | GPIO34 ← 노드 N |
| PT 컬렉터 | — | `3V3` (**5 V 절대 금지**) |

**OP앰프 0개 · 커패시터 0개.** LM358이 4핀 모듈로 확인되면서 OP앰프를 전면 제거했다. 신호처리는 하드웨어가 아니라 소프트웨어(락인)가 한다.

**락인 검출 — 커패시터 없이 잡음을 잡는 방법**

| 항목 | 값 |
|---|---|
| 변조 $f_0$ | 510 Hz (스윕 510·530·610·670·730·790) |
| 주기당 단계 | 8 — `{100,110,111,110,100,010,001,010}` |
| 적분시간 | **10 s = 40,800 샘플** (0.1 s 정수배 → **50 Hz·60 Hz 동시 널링**) |
| 출력 | $S = A_\text{sig}/A_\text{sense}$, 암 벡터 $(I,Q)$ 차감 |
| 온도보정 | DS18B20, $a$ 자동회귀 (한계 $\|a\| \le$ 1.5 %/°C) |
| 측정 주기 | 1 시간 |

$A_\text{sense}$ 로 나누는 구조라 LED 광출력 드리프트·전원 변동이 비율에서 소거된다. GPIO36의 ESP32 에라타(DC −90 mV)도 **상수 오프셋은 $f_0$ 성분이 0이라 락인 진폭에 영향이 없다** — 실측에서 $A_\text{sense}$ 가 이론값 129 mV 대비 124 mV(오차 4 %)로 확인됐다.

**광로 $L$ = 50 mm 확정 — 30 mm 기각**

| | 30 mm | **50 mm** |
|---|---|---|
| SNR | 190 | 179 |
| 감도 | 0.75 %/NTU | **1.25 %/NTU** |
| T3가 허용하는 드리프트 | 1.5 % | **2.5 %** |
| 최악(선형합) 예산 | **1.85 % ✗** | 1.85 % ✓ |

> 이 프로브의 병목은 **잡음이 아니라 드리프트**다(예산·실측 두 번 확인). 30 mm는 병목이 아닌 쪽에서 SNR 6 %를 벌면서 병목 쪽 여유 40 %를 내준다 — **성립하지 않는 거래**다. 부수 근거: 5회 반복 추세가 10 mm에서 −2.65 %인데 50 mm에서 −0.27 %(정렬 오차 영향이 $1/L$).

**파장 850 nm 확정 — 940 nm 기각**

| | 850 nm | 940 nm |
|---|---|---|
| $L$=50 mm 투과율 | **≈80 %** | **≈27 %** |
| 온도 의존성 | 무시 가능 (±0.2 %) | **0.5~0.8 %/°C → 수온 ±3 °C에서 ±2 % 이상** |
| ISO 7027 대역(860±60) | **안** | 밖 |

> 940 nm는 물의 970 nm 흡수띠 **가파른 사면 위**에 있다. 물 흡수 자체가 온도로 변하면 그 변화는 **탁도 변화와 구분되지 않는다** — 전체 예산 2.5 %를 이 항목 하나가 먹는다. 온도보정으로 흡수할 수는 있지만 그러면 **설계 전체가 온도보정 정확도에 인질이 된다.** 850 nm는 두 문제가 동시에 사라진다.

**실측 근거 (2026-07-27, 공기 중)**

| 거리 | 노드 N | RSD(5회) |
|---|---|---|
| 10 mm | 1.0728 V | 1.09 % |
| 30 mm | 0.6452 V | 0.25 % |
| **50 mm** | **0.3658 V** | **0.23 %** |

감쇠지수 **−0.593** — **"$1/L^2$ 가 전혀 아니다."** (거리와 무관한 미광이 섞여 있다는 뜻이고, V5 하우징 통과 후 재측정하면 50 mm 값은 0.366 V보다 낮아진다.)

**펌웨어 성능 (demo_v2, 브링업 실측 근거 5건 반영)**

- $R_5$ = 151 kΩ 확정, ADC 감쇠 11 dB → 0 dB, 예열 20 → 60 s (냉시동 100 s간 $S$ 가 −0.335 % 단조 감소했기 때문)
- **잡음 1σ = 0.043 NTU** — 요구 1 NTU 대비 **23배 마진**
- 듀티 0.28 % → T9(<5 mA) 통과

**요구사항 대조 (T1~T11)**

| 요구 | 확정 설계 | 상태 |
|---|---|---|
| T1 5 NTU 검출 | SNR 179 | 여유 큼 |
| **T3 드리프트 <2 NTU/7일** | 최악 1.85 % | **여유 0.65 % ← 지배 제약** |
| T6 <1 NTU (1σ) | 36:1 | 여유 큼 |
| T7 <60 s | 10 s | 통과 |
| T8 외부광 | 락인 + 검정 패키지 + 개구 | **V4·V5 미검증** |
| T10 ≤60 mm | 50 + 10 | 상한 정확히 사용 |

**남은 관문은 V5 하나다.** 공기 중 시험에서 암 잔류가 **신호의 28 %**(합격선 5 %)로 나왔다 — 하우징이 없었으니 예상된 결과이고, 주파수 특성이 진짜 신호와 거의 같아(−8 % vs −10 %) **광학적 우회**로 판정됐다. 하우징으로 잡히는 종류다.

#### (4) 통신

ESP32 → **BLE** → 앱. Capacitor 네이티브 플러그인(`@capacitor-community/bluetooth-le`)이 처리하고 화면 코드는 그대로 재사용한다.

### 4-2. 어플리케이션 설계

#### (1) 아키텍처 — 물리와 UI를 분리했다

| 파일 | 크기 | 역할 |
|---|---|---|
| `app_demo.html` | 89 KB | UI · 탭 · BLE · 센서 고장판정 · 알림 디바운스 · XSS 이스케이프 |
| `do_engine.js` | 26 KB | DO 수지 · 폭기 진단 · ROM 추론 (rev.C) |
| `rom_model.js` | 210 KB | CFD 315케이스로 학습한 A층 ROM 계수 |

- **엔진은 전역을 참조하지 않는다.** 앱이 `syncEngine()` 으로만 상태를 밀어넣는다 → 물리 계수를 고칠 때 `app_demo.html` 을 열지 않는다
- **3단 폴백:** `rom_model.js` 부재 → 근사식(지도만 비활성) / `do_engine.js` 부재 → 옛 선형근사(앱은 계속 동작)
- 병합 이력(8/1): 안드로이드 셸을 베이스로 두고 SW팀 물리엔진만 이식. **`estimateHealth()` 자리표시자 → `DOEngine.estimate()`**

#### (2) 계산 사슬 (앱 안에서 실제로 일어나는 일)

```
사진 → Gemini(type/size/rel 요청) → analyzedObjects
                                        │
                                        ▼
                          obs_mask 8×8×12 점유율 768D
                                        │  PCA 6성분 + RidgeCV
                                        ▼
                                    χ(x) 장
                                        │
   C = C*(T) − R_total / (V · K_La)  ←──┘        R_total = 어류 + 유기물(탁도) + 식물(주야)
                                        │
                                        ▼
                        최저 지점 기준 등급 (DO_CRIT = 6.0 단일)
```

| 항목 | 값 |
|---|---|
| $C^*(T)$ | Benson–Krause 담수 포화, $C^*(25)$ = **8.2635 mg/L** |
| $K_La$ | (플룸·에어스톤높이 + 자유수면) × 수위 × $\theta_a^{(T-25)}$ |
| $V$ | 사용자 수조 치수 × 수위 (기준 20.7 L) |
| ROM skill (5-fold CV) | $u_\text{fish}$ 0.633 · $u_\text{sod}$ 0.339 · 전량격자 0.603 |
| 출력격자 | 8×8×12 |

> **등급은 평균이 아니라 최저 지점 기준이다.** 평균이 안전해도 바닥 구석이 임계(6.0 mg/L) 미만이면 그 물고기는 실제로 숨이 차다.

#### (3) 폭기 전력 연속 입력 (8/3 기계 → SW 인계, N4 해소)

`KLA_EFF` **4단계 하드코딩 → `pumpPowerW` 연속 스칼라**. 바뀌는 것은 입력 하나뿐이고 하류(플룸/수면 분리, $z_\text{start}$ 레버, 수위·수온 보정, ROM)는 전부 그대로다.

$$P \to Q_\text{air} \to U_{gs} \to (\alpha_g,\ W)\ \text{고정점} \to a = 6\alpha_g/d_b \to K_La \to \text{DO}$$

- 앵커: $P_0$ = 2.5 W (EX1 실험 사용 펌프), $Q_0$ = **1.200 ± 0.002 L/min** (그 펌프로 실측) → $c$ = **0.480 L/min/W**
- 1변수 대수방정식으로 축약 (CFD를 부르지 않는다): $\;0.3009\,x^{1.511} + 0.0578\,x = 0.3587\,(P/2.5)$, $x \equiv \alpha_g/\alpha_{g0}$
- 출력: $\;\boxed{K_La(P) = 2.160\,x + 0.444}\;$ [/h] — **플룸항만 $x$ 로 스케일**, 자유수면 0.444는 폭기를 꺼도 남는 바닥값
- UI 슬라이더용 실용 근사(0.5–6 W에서 오차 <1 %): $K_La \simeq 2.160(P/2.5)^{0.70} + 0.444$
- $P = P_0$ 에서 $x = 1$ 이 정확히 성립 → 확정 상수(0.1785 / 1.751 / 0.3009 / 2142 / 2.604)를 오차 없이 재현

**단, 유일한 미검증 고리는 $Q_\text{air} = cP$ 의 선형성과 절편 0이다.** 앵커점 자체는 실측이다.

#### (4) 알림 — 세 지표 독립 판정

수온 · 탁도 · **용존산소**를 각각 별도 채널로 판정한다. DO는 센서로 직접 재는 값이 아니라 두 센서값에서 계산되지만, **수온·탁도가 각각 정상 범위여도 둘이 겹치거나 사육부하가 크면 산소만 먼저 무너질 수 있다.** `commitTransition` 디바운스 + 알림로그 + 미읽음 배지 + danger/warn 시 OS 알림.

`npm run build` (app_demo.html → www/index.html) → `npx cap add android` → `npm run sync`(BLE 권한 자동 주입) → **APK 4.9 MB** (`demo_apk/aqua-sense.apk`)

#### (6) 시연 시나리오 (권장 순서)

1. 어항 사진 촬영 → Gemini 인식 결과(바위·수초·마릿수·폭기 위치) 표시
2. 인식 결과 → 4×9 위험맵 렌더 — **"이 칸일 확률 67 %, 상위 25 % 안일 확률 100 %"** 로 설명

#### (7) 발표 전에 반드시 고칠 것 / 질문받으면 정직하게 답할 것

정합성 검토(8/2)에서 상충 5건이 나왔고, 방향이 **전부 false-safe**다. 시연에 직접 걸리는 순서로:

| # | 문제 | 숫자 | 조치 |
|---|---|---|---|
| B3 | 앱 정본 $K_La$ **3.618 /h가 논문에 0건** (폐기된 $\alpha_g$=0.257 기반) | 허용 부하 환산: 3.618 → **28.3마리** / 2.604(CFD 확정) → 20.3 / 2.417(실측) → **18.9마리** ⇒ **19마리가 한계인 어항에 28마리까지 "충분"(+50 %)** | 2.604로 교체 + **시연 DO 절대값 재계산 필수** |
| B2 | `romShapeValid()` = `aerationLevel === '보통'` 인데 그 '보통'의 정의가 **$Q_\text{air}$ 2 L/min**(실측 1.200의 폐기 어림값) | 실물 운전점 Su≈1.75는 `EX2_X` 게이트가 **불합격**시킨 조건(IoU 0.597 < 0.80, 정체분율 +73 %) | 게이트 **부호가 뒤집혀 있다** — 재정의 |
| B1 | 엔진 헤더의 "이류 12.8 s vs 소비 9.5 h → 2,673배 → 완전혼합" 논증 | $t_\text{mix}$ 측정에서 **철회된 바로 그 논증** | 0-D mean을 "균질 가정 값"이 아니라 **"총량 수지값"**으로 재정의 표기 |
