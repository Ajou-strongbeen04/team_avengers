## 2. 범위 재정립 (이것이 이 문서의 본론)

### 2.1 세 갈래로 나눈다

| 트랙 | 무엇을 | 어디서 보여주나 |
|---|---|---|
| **A. 데모 앱 (HTML)** | 예정했던 다항목을 **전부 넣은** 시연용 앱 | 27인치 모니터 (노트북 HDMI) |
| **B. 센서 실물** | **이미 출력된 부품을 조립만** 해서 테이블에 놓는다 | 테이블 |
| **C. 포스터** | 나머지 전부 — 물리·실험·검증·한계 | A0 판넬 |

### 2.2 트랙 A — 데모 앱: 확정 사항

- **형식: HTML 단일 파일.** Capacitor·APK·안드로이드 스튜디오 경로를 **전부 내려놓는다.** `demo_html/step03/android/`, `demo_apk/aqua-sense.apk`는 건드리지 않고 그대로 둔다(폐기 아님, 동결).
- **실행 방식: `file://` 직접 열기 제외, 로컬 서버(localhost)로 구동한다 (2026-09-16 결정).** `산출물/app` 폴더 전체를 전시 노트북 로컬 디스크(예: `~/app`)로 옮긴 뒤 `run_server.sh`로 `python3 -m http.server`를 띄우고 `http://localhost:8000/app_demo.html`로 접속한다. OneDrive 동기화 경로에서 직접 열지 않는다. 상세: `app/README.md` "실행 방법".
- **성격: 데모 전용.** 센서 실연결(BLE) 없음. 값은 시나리오 데이터로 움직인다.
- **플로우: 기존 그대로 간다.** `app_demo.html`의 8탭 구조 — `home` / `sensor` / `chat` / `alerts` / `notices` / `info` / `tank-settings` / `sensor-settings` — 를 유지한다. **화면 순서와 정보 구조는 손대지 않는다.**
- **디자인: 애플 스타일로 전면 교체.** §4에서 규정한다.
- **내용: 다항목 전량 탑재.** §3에서 규정한다.

### 2.3 트랙 B — 센서: "조립만"의 정확한 뜻

**한다**

- 이미 출력된 P1~P5를 조립한다 (`05_외피설계.md` §12 부품표 · §11 조립 지침)
- 모서리 사포 마감 (#400 → #1000), 열수축튜브, 외관 정리
- 테이블에 세워 둘 거치 방법 하나

**안 한다 — 전량 동결**

- `02_설계.md` §10 **브링업 단계 1~5 전부** (LED 구동·수광·락인·물 투입·장기)
- **배선 작업 전량** — 09-01~09-16 논의에서 확인된 P2 광학존 관통 배선 모순(genus 3 = 관 1 + 슬롯 2, 배선 통로 없음)은 **설계 재작업 사안이므로 이번 일정 밖으로 내보낸다**
- 에폭시 포팅 · 소자 실장 · 방수 · V1~V6 검증
- Φ10 유지 / 광학존 분리 / 후방산란 / 벽 안 배선채널 — **4개 안의 선택 자체를 보류한다.** 대회 후에 판정한다

> **즉 전시물은 "동작하는 센서"가 아니라 "설계가 끝난 기구 실물"이다.** 이 구분을 발표에서 흐리지 않는다. 물으면 "기구 설계와 출력까지 완료, 광학 실장은 배선 경로 재설계 중"이라고 답한다. 평가기준의 **"한계(개선)사항에 대한 인식"(검증 20점 항목)**은 이렇게 답할 때 오히려 점수가 붙는 자리다.

### 2.4 트랙 C — 포스터가 맡는 것

앱과 실물이 못 보여주는 나머지 전부: 문제 정의, 물리 모델, 실험 1·2·3, 검증 결과, 한계, 확장 로드맵.

`02a_다항목확장_검토_20260807.md` §2 전수 목록과 §9 우선순위 판정안을 그대로 쓴다. **새 항목을 발명하지 않는다.**

**넣지 않는 것** — 02a가 직접 제외했거나 Tier 4·보류로 내린 것: D1 수온 부력(등온 가정을 깨야 함) · D2 염분 성층 · E2 조류(광량장 필요) · B5 인산(급성 사인 아님) · E3 사료 분산. 그리고 02a "프레임 밖" 4항목(질병, 기계 고장, 개체 행동, 수질 외 급성 요인)은 앱에도 넣지 않는다.

### 3.1 표시 규약 — 이걸 안 지키면 발표에서 깨진다

`02a`는 전부 **검토안·설계 단계**다. §10에 미확정 [R#] 10건이 남아 있고, DO 외에는 계산된 적도 검증된 적도 없다.

- 앱 화면에서 **DO만 "측정·계산"**이고, 나머지 11항목은 **"확장 예정 — 설계 완료, 미검증"** 배지를 단다. 배지 없는 수치를 화면에 띄우지 않는다.
- 값은 **시나리오 프리셋**임을 화면 어딘가에 상시 표기한다("데모 데이터").
- 발표에서 "다 됩니다"가 아니라 **"유동장 한 번 계산으로 N개 항목이 같은 틀에서 풀린다 — 그게 이 구조의 핵심이고, DO로 그걸 증명했다"**로 말한다. 이것이 02a §1의 논지이고 확장성 20점에 직접 걸린다.
- 어항 규격은 데모 규격 **47 × 21 × 21 cm ≈ 20.7 L**로 고정 (`04_어플리케이션/README.md`).

### 3.2 시나리오 3개 (5분 안에 도는 분량)

| # | 시나리오 | 보여주는 항목 | 길이 |
|---|---|---|---|
| S1 | **정상 → 여과 저하** | DO 하강 + TAN·NO₂ 상승 + pH 하강 → 위험 판정 | 60 s |
| S2 | **환수 직후** | 잔류 염소 국소 고농도 + 알칼리도 회복 | 30 s |
| S3 | **약품 투여** | 분산·혼합시간 — 소스 없는 순수 이송, 시각적으로 가장 강함 | 30 s |

S3가 02a §9에서 **"시연 최강"**으로 꼽힌 항목이다. 시간이 모자라면 S2를 버린다.

## 4. 디자인 — 애플 스타일 (플로우 불변, 외피만 교체)

### 4.1 원칙

**구조·타이포·여백·색으로 만든다. 애니메이션과 그림자로 만들지 않는다.** 화면에 새 기능을 추가하지 않고, 기존 8탭의 요소를 애플 디자인 문법으로 다시 입힌다.

**스크롤은 화면에 절대 등장하지 않는다.** 한 화면(한 탭·한 카드)에 내용이 다 안 들어가면 스크롤로 흘리지 말고, 화면 자체를 여러 단계로 쪼갠다. 단계 전환은 §4.2의 모션 토큰(0.3s `cubic-bezier(0.32, 0.72, 0, 1)`)을 적극 활용해 슬라이드/페이드로 넘긴다 — 27인치 모니터로 먼 거리에서 보는 발표 데모라 스크롤 동작 자체가 관객에게 안 보이거나 실수로 안 눌려서, 화면이 멈춘 것처럼 보이는 리스크가 크다.

### 4.2 규격 (구현 시 이 표를 따른다)

| 항목 | 값 |
|---|---|
| 폰트 | `-apple-system, "SF Pro Text", "Apple SD Gothic Neo", "Pretendard", sans-serif` — 시연 노트북이 맥북이면 네이티브로 렌더된다 |
| 숫자 | `font-variant-numeric: tabular-nums` — 값이 바뀌어도 자릿수가 안 흔들린다 |
| 타이틀 | 라지 타이틀 34px Bold → 스크롤 시 17px Semibold 네비바로 축소 |
| 본문 계층 | Primary / Secondary / Tertiary 3단 (불투명도 1.0 / 0.6 / 0.3) |
| 강조색 | systemBlue `#007AFF` 1개만. 상태색은 systemGreen `#34C759` / systemOrange `#FF9500` / systemRed `#FF3B30` |
| 배경 | 그룹 배경 `#F2F2F7`, 카드 `#FFFFFF` (다크: `#000000` / `#1C1C1E`) |
| 리스트 | **인셋 그룹 리스트** — 카드 radius 10px, 좌우 마진 16px, 셀 높이 44px, 구분선은 좌측 16px 인셋 |
| 그리드 | 8px 배수. 카드 내부 패딩 16px |
| 탭바 | 하단 고정 · `backdrop-filter: saturate(180%) blur(20px)` · 상단 hairline 0.5px |
| 모션 | 0.3s `cubic-bezier(0.32, 0.72, 0, 1)` 만 사용. 그 외 애니메이션 금지 |
| 다크모드 | `prefers-color-scheme` 대응. **전시 모니터 밝기를 모르므로 라이트를 기본으로 고정하고 다크는 보조** |

### 4.3 화면별 적용 (플로우는 그대로)

| 탭 | 지금 | 애플화 |
|---|---|---|
| `home` | 상태 카드 + 위험 감지 | 라지 타이틀 + **상태 1개를 큰 숫자로**, 나머지는 인셋 리스트 |

### 4.4 27인치 모니터 대응

앱은 폰 비율인데 모니터는 27인치 가로다. **폰 목업 프레임 안에 앱을 넣고 화면 중앙에 배치**하고, 남는 좌우에 지금 도는 시나리오 이름과 한 줄 설명을 띄운다. 폰 화면을 27인치로 늘리면 레이아웃이 깨지고 애플 스타일의 여백 비율이 무너진다.
