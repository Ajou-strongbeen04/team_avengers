# Sensors 스코프 정합 프레이밍 — 이 경로의 승부처

> 팀 漁벤져스 · 상위: `../00_전략/제출전략.md` §4
> 문제 한 줄: **Sensors 편집자에게 이 원고는 "센서가 없는 CFD 논문"으로 읽힐 수 있다.** desk reject의 가장 큰 원인.

---

## 1. 진단 — 왜 위험한가

원고의 무게중심을 그대로 두면 이렇게 보인다:

```
URANS CFD → POD → LLM 추론 → 위험맵     ← 센서가 어디에도 없다
```

Sensors 편집자가 찾는 것은 **측정(sensing)이 논문의 주어인가**이다. 우리 원고에서 센서는 현재 "온라인 교정용 부속"으로 서술돼 있다. 이대로면 "Applied Sciences나 Fluids로 가라"는 답을 받는다.

---

## 2. 처방 — 프레이밍 전환

**전환 전 (위험):**
> 사진으로 BC를 세워 CFD를 돌리고, 저가 센서로 계수를 보정한다.

**전환 후 (안전):**
> **카메라를 공간 센서로 쓴다.** 단일점 DO 프로브가 못 보는 공간장을, 사진(비접촉 관측) + 저가 프로브(단일점 실측) + 물리모델을 융합한 **가상 다지점 센서(virtual multi-point sensor / soft sensor)** 로 복원한다.

핵심은 프레임 이름 하나다. 이 논문은 **소프트센서 논문**이다:

| 소프트센서 문법 | 우리 구성요소 |
|---|---|
| 관측 입력 (비접촉) | 수조 사진 → VLM 기하·위상 |
| 관측 입력 (접촉·저가) | DS18B20 온도 · IR 탁도 · 단일점 DO |
| 물리 기반 관측 모델 | URANS + 이송확산, POD 기저 |
| 추론기 | 물리기저 구속 LLM in-context 추론 |
| 캘리브레이션 | 재폭기 시험 → $K_La_\text{eff}$, κ |
| 출력 (센서가 못 주는 것) | 4×9 저산소 **공간** 위험맵 + 불확실도 |

→ 이 표가 곧 **Figure 1의 캡션 논리**이자 커버레터 첫 문단이다.

## 3. 원고 레벨 조정 지침

| 위치 | 조정 |
|---|---|
| **Title** | 그대로 두되 부제나 키워드에 `low-cost sensing` / `virtual sensing` 신호를 넣는다 |
| **Abstract 1문장** | "단일 DO 센서는 공간분포를 못 본다"로 **센서 한계에서 출발**. 현재 v2 초록이 이미 이렇게 시작함 — 유지 |
| **§1 Introduction** | 세 병목 앞에 **"측정의 병목"**을 배치. 다지점 계측 비용 → 왜 센서로 못 푸는가 |
| **§1.3 Related work** | ④ 저가 IoT DO 계보를 **맨 앞으로**. 우리와 같은 커뮤니티임을 먼저 보이고 "그들은 단일점·시간, 우리는 공간·물리"로 차별화 |
| **§2 System Overview** | 하드웨어 구성(카메라 + 저가 프로브)을 **먼저** 그리고, CFD·LLM을 그 뒤 추론 엔진으로 배치 |
| **§3** | 순서 유지. 다만 §3.2 앞에 "관측 모델(observation model)" 이라는 프레임 문장 추가 |
| **§4** | **센서 실측 결과(§4.1 재폭기)를 결과부 맨 앞에** 유지 — 이미 그렇게 배치돼 있음 |
| **§5.3** | 실제 디바이스(`../../../05_제품/`) 사양·BOM을 구체적으로. "논문용 가상 시스템"이 아님을 증명 |

---

## 4. 하지 말아야 할 것

- ❌ 억지로 센서를 늘리지 않는다. 있는 것(온도·탁도·단일점 DO·카메라)으로 프레임만 바꾼다
- ❌ 재폭기 $K_La$ 캘리브레이션을 novelty로 세우지 않는다 (신규성 약)
- ❌ CFD 방법론 상세를 §3 앞쪽으로 끌어올리지 않는다 — 유체 저널처럼 보이는 순간 스코프 아웃
- ❌ "dead-spot" 사용 금지 (`../../../00_운영/용어사전.md`)
