# 01 · 기하인식 개요

> 트랙: 카메라 사진 → 기하·위상 인식 → 경계조건(BC) 자동 추출
> 방식: **VLM(Gemini류) 기반** (학습 불필요, 프롬프트·파싱 중심)
> 정합: `04_소웨.md` §2 · `03_논문/` (BC·소스항 정의) · 특허 C2·C3

## 1. 목표

기존 CFD는 케이스마다 경계조건·소스 위치를 **수작업**으로 세팅한다.
이를 **수조 사진 1장 → VLM 분석 → 물리모델 경계조건 자동설정**으로 대체한다.
이번 단계의 목표는 축소모델(ROM)이 나오기 전에 **BC를 확실하게 인식하는 인식기**를 먼저 완성하는 것.

## 2. 입력 / 출력

- **입력**: 수조 정면 사진 2장 (데모: 47×21×21 cm 어항)
- **인식**: 수조 형상·치수(일단 데모는 고정), 장식물(바위 등) 위치, 수생식물 위치, 기포기 토출 위치, 어류 마릿수·크기(사육부하)
- **출력**: 경계조건·소스항 위치 매핑 ($\Omega_\text{air}$, $\Omega_\text{filter}$, $\Omega_\text{fish}$, 장애물 영역) → 정규화 좌표 JSON (스키마: `03_BC_출력스키마.md`)

## 3. 정직한 범위(envelope) — 반드시 지킬 것

사진에서 잡는 것은 **기하·위상**이다. PDE가 요구하는 **정량 계수**($\text{SOD}_{20}$, $k_L$, 플룸 $\alpha_g/d_b$, OCR)는 사진에 안 보인다.

- 사진 인식 = 위치·형상·개수 (WHERE / WHAT / HOW MANY)
- 정량 계수 = 센서로 온라인 교정 (사전분포 prior 범위 내)
- VLM 기하 서술자는 **ROM 입력공간으로 매핑**되어야 한다 (사용자마다 풀 CFD 불가)

이 경계를 흐리지 않는다. "사진으로 DO를 직접 읽는다"가 아니라 "사진으로 물리모델의 무대(geometry+BC)를 세운다"이다.

## 5. 좌표계 규약 (사진좌표)

- 원점: 수조 정면 좌하단 (0,0,0)
- 축: x=폭(47, 좌→우), y=높이(21, 하→상), z=깊이(21, 앞→뒤)
- 사진은 2D → 깊이 z는 VLM 추정 + 기본값(중앙면) prior. 상세는 `02`·`03` 참조.
- 모든 좌표는 **정규화([0,1])** 로 출력 후 실치수(cm)로 스케일. (데모 스케일: x×47, y×21, z×21)

> ⚠️ **이건 사진좌표다. CFD좌표와 2·3축이 뒤바뀐다** — CFD는 $y$=폭, $z$=수심(상향). $B=d=21$ cm라 숫자로는 안 드러나지만 변환을 빠뜨리면 장애물이 90° 돌아간다. **변환식과 스키마 필수 필드는 `03_BC_출력스키마.md` §0에 확정돼 있다. VLM은 사진좌표만 채우고, 어댑터가 CFD좌표를 생성한다.**
